# Velorian

Локальный AI-чат на React и FastAPI. Основные модели работают через Groq; Gemini можно подключить отдельно через Google AI Studio. Документы обрабатываются локально, OCR выполняется через Tesseract, а веб-поиск использует инструменты выбранного AI-провайдера.

## Требования

- Python 3;
- Node.js и npm;
- Bash (на Windows подойдёт Git Bash);
- Tesseract с языками `rus` и `eng` — только если нужен OCR изображений.

## Локальный запуск

1. Скопируйте `backend/.env.example` в `backend/.env`.
2. Укажите в `backend/.env` существующий `GROQ_API_KEY`. Чтобы включить Gemini в селекторе моделей, дополнительно укажите `GEMINI_API_KEY`.
3. Из корня проекта установите зависимости:

   ```bash
   ./setup.sh
   ```

4. Запустите backend и frontend:

   ```bash
   ./dev.sh
   ```

5. Откройте `http://localhost:5173`. При первом входе создайте локальную учётную запись.

`dev.sh` также открывает документацию API на `http://127.0.0.1:8000/docs`. Для остановки обоих процессов нажмите `Ctrl+C`.

Без Tesseract изображения сохраняются и показываются, но локальный OCR для них недоступен.

## Проверки

Backend-зависимости для тестов устанавливаются отдельно от основного окружения:

```bash
cd backend
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

В Windows используйте `.venv/Scripts/python.exe` вместо `.venv/bin/python`.

Проверки frontend:

```bash
cd frontend
npm test
npm run lint
npm run build
```

E2E-тесты запускаются отдельно командой `npm run test:e2e` из каталога `frontend`.

## Production через Docker Compose

1. Скопируйте `.env.production.example` в `.env.production` и замените демонстрационные значения и секреты.
2. Выполните:

   ```bash
   docker compose --env-file .env.production up --build -d
   ```

3. Приложение будет доступно на `http://localhost:8080` или порту, указанном в `APP_PORT`.

Production-конфигурация использует PostgreSQL и S3-совместимое хранилище. При размещении за HTTPS-прокси установите `COOKIE_SECURE=true`. Метрики Prometheus доступны по `/metrics`, проверки состояния — по `/health/live` и `/health/ready`. Для нескольких экземпляров приложения in-memory rate limiter следует заменить на общее внешнее хранилище, например Redis.

## Возможности

- локальные учётные записи, история диалогов и ветки сообщений;
- оценки ответов и сохранение полезных материалов в базу знаний;
- база знаний с фильтрами и подходами;
- долговременная структурированная память пользователя;
- загрузка PDF, DOCX и текстовых файлов с локальным извлечением текста и лексическим RAG;
- OCR изображений и дополнительный анализ vision-моделью;
- веб-поиск для отдельного запроса;
- выбор GPT-OSS 120B, Qwen 3.8 или Gemini 3.8 Flash.

## Модели, файлы и поиск

- GPT-OSS и Qwen используют `GROQ_API_KEY`, Gemini — отдельный `GEMINI_API_KEY`.
- Модель по умолчанию задаётся переменной `DEFAULT_CHAT_MODEL`: `gpt-oss-120b`, `qwen-3.8` или `gemini-3.8-flash`. Модели без настроенного API-ключа показываются в меню как недоступные.
- PDF, DOCX и поддерживаемые текстовые форматы извлекаются локально и могут использоваться в контексте диалога.
- Изображения обрабатываются локальным OCR и, если включено, vision-моделью `qwen/qwen3.8-27b` через Groq. Если vision-модель недоступна, используется результат OCR. Vision можно отключить через `ENABLE_VISION=false`.
- Веб-поиск включается для отдельного запроса переключателем у поля ввода. Для Groq используется `browser_search`, для Gemini — Google Search.
